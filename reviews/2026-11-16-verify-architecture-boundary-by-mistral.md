## 2. Wrong facts in detail, and what they change

1. **`generic_pt` total is 6,310 lines, not 6,772** (§2.1, line 39). All four sub-counts are exact (1,369 + 1,511 + 1,330 = 4,210 named; the remaining ~2,100 are the other headers). Changes nothing in the recommendation: direction 1 (one page-table code from a description) does not depend on the total; only the cited number must be corrected.
2. **16 KB granule + 48-bit IA root is two concatenated tables (4096 entries), not 2 entries** (§2 table, line 65). DDI 0487H.a p. 4819 is explicit. This *strengthens*, not weakens, the draft's own recommendation to standardise on 47 bits with the 16 KB granule (3 levels, one 2048-entry root). The 47-bit row is correct.
3. **RISC-V leaf rule wording** (§10, line 511): a leaf PTE has R **or** X set; W without R is a page fault, not a leaf. The draft's separate claim "W without R reserved" is right, but "leaf = R, W or X" is wrong. Affects only the wording of the format description's leaf predicate in direction 1's contract rule — the check "an entry with W and not R is invalid" stays.
4. **"No machine-readable register data from Intel" is wrong** (§4.3 line 159, §10 line 515, §1 line 27). Intel publishes an executable-spec XML corpus (`github.com/intel/SDM`, announced 2026-08-20): 741 per-instruction XML files with pseudocode (including CPL≠0 checks), MSR category XML, definitions/intrinsics XML. But its licence is restrictive (no modifications or derivatives) and it carries **no RING0-style privilege attribute** (0 hits), so **the recommendation "on x86-64 use Intel XED's instruction data" stands unchanged**; only the justification sentence "since no vendor publishes registers in machine-readable form" must be reworded (Intel's data exists but is not openly licensed and has no privilege attributes; AMD CPU: none found, not provable).
5. **UBIOS "nor UEFI except in comparisons"** (§5.7, line 315): the extracted PDF text contains **zero** occurrences of "UEFI". The claim should read "the extracted text never mentions UEFI" (figures not searched). No recommendation depends on it.
6. **Barrelfish `.dev` count 92 → 84 top-level** (272 recursive) (§4.5). Numeric only; the point (a large machine-readable device corpus feeding Mackerel/Sockeye) is unchanged.
7. **Limine picoefi is not a `.gitmodules` submodule at 033b597** (§5.4b line 262, §10): it is cloned by `bootstrap:73` at a pinned commit. Wording only; the "not checked out" caveat still applies.
8. Minor: `amd/iommu.c:2169`/`riscv/iommu.c:839` in §2.1 line 48 are off by one (actual 2170/841).

**Recommendations:** none of the five headline recommendations (adopt the format description; common entry path; generated registers with XED on x86-64; UEFI stub + firmware-neutral hand-over; leave Velosiraptor) falls or weakens because of a wrong fact. Items 1, 6, 7, 8 are numeric/wording. Item 2 supports the draft's 47-bit choice. Item 3 is a one-word correction in the description rule. Item 4 keeps XED as the x86-64 source but requires rewording the "no vendor publishes" justification.
